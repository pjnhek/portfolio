# Phase 1 — UI Design Contract

> Visual and interaction contract for the Foundation Slice. Generated by gsd-ui-researcher from CONTEXT.md (D-01..D-08), CLAUDE.md (locked stack), RESEARCH.md (architecture + pitfalls), and REQUIREMENTS.md (FOUND-01..13). Verified by gsd-ui-checker.

**Tone arbiter (binds all close calls in this contract):** "engineering artifact, not designer's playground." Visual reference is `huyml.co` — but more minimal. Optimize every choice for a recruiter scanning at 375px for 60 seconds.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (hand-rolled primitives, no shadcn install) |
| Preset | not applicable |
| Component library | none |
| Icon library | `lucide-react@^0.460` (per CLAUDE.md; **not used in Phase 1** — first icon usage is Phase 2 Contact section, but the dependency is installed Day 1 per RESEARCH.md to lock the icon system choice) |
| Font (sans) | `Geist` via `next/font/google`, weights `[400, 500]`, `display: 'swap'`, CSS var `--font-sans` |
| Font (mono) | `Geist_Mono` via `next/font/google`, weights `[400, 500]`, `display: 'swap'`, CSS var `--font-mono` |

**Why no shadcn in Phase 1:** CONTEXT.md locks 5 hand-rolled primitives (`Section`, `NumberedHeading`, `Tag`, `ExternalLink`, `ArchitectureDiagram`). None of them require Radix/Base UI behavior. shadcn primitives become attractive only when a Dialog/Tooltip/Tabs surfaces (no such requirement before Phase 2 at earliest, and PROJECT.md's "View Source" arbiter favors visible hand-rolled primitives over vendored ones for this specific aesthetic). Decision is reversible: a future phase can run `pnpm dlx shadcn@latest add dialog` per-component without retrofitting v1.

**Why CSS-first Tailwind v4 (not `tailwind.config.js`):** Locked by FOUND-02 and CLAUDE.md. All tokens below live in `app/globals.css` under `@theme`. No JS theme.

## Spacing Scale

Declared values (multiples of 4 only). Lives as Tailwind v4 `--spacing-*` (or default Tailwind v4 spacing primitive — Phase 1 keeps the default 4px-grid and only adds named tokens where the contract needs them).

| Token | Value | Usage |
|-------|-------|-------|
| `--space-1` | 4px | Hairline gaps, tag inner padding |
| `--space-2` | 8px | Inline element spacing (anchor number → heading text) |
| `--space-3` | 12px | Compact stack (tag row gaps) |
| `--space-4` | 16px | Default element spacing, paragraph spacing |
| `--space-6` | 24px | Tight intra-section spacing |
| `--space-8` | 32px | Heading-to-body within a section |
| `--space-12` | 48px | Section inner padding (mobile) |
| `--space-16` | 64px | Vertical section rhythm (mobile) |
| `--space-24` | 96px | Vertical section rhythm (≥ md, desktop) |
| `--space-32` | 128px | Page top/bottom gutter (desktop) |

**Section vertical rhythm (binding):**
- **Mobile (< 768px):** 64px between major numbered sections (`py-16` equivalent applied to each `Section`)
- **Desktop (≥ 768px):** 96px between major numbered sections (`md:py-24` equivalent)
- **Hero top padding:** 96px mobile / 128px desktop (the hero gets extra breathing room — it's the LCP element)

**Horizontal page gutter (binding):**
- **Mobile (< 768px):** 24px each side (`px-6` equivalent)
- **Tablet (≥ 768px):** 48px each side (`md:px-12` equivalent)
- **Desktop (≥ 1024px):** Centered content column **max-width 720px** (~`max-w-2xl` + a touch; finalized at implementation). Page itself remains full-width; only the prose column is capped. This matches huyml.co's narrow single-column read and keeps line length within 60–75ch at 17–20px body.

**Exceptions:**
- Touch targets for any interactive element (Phase 1: only `ExternalLink`) must be ≥ 44×44 px effective hit area. If visual size is smaller, expand via padding — do not shrink the visual.
- The `ArchitectureDiagram` `<figure>` may break out of the content column to full container width on mobile so SVG diagrams render at native size (DIAG-03 anticipates this in Phase 2).

## Typography

Body floor 17px per CONTEXT.md D-05. Scaling via `clamp(min, vw-based, max)` per FOUND-06. Line-heights are binding (D-05). Geist Sans for prose; Geist Mono reserved for the four enumerated uses below (D-05, D-06).

| Role | Size (clamp) | Weight | Line Height | Font | Notes |
|------|--------------|--------|-------------|------|-------|
| `caption` (mono) | `clamp(13px, 0.85rem, 14px)` | 400 | 1.4 | Geist Mono | Section anchor numbers (`01.`), tech chips, metric callouts, file-path or code-like inline text |
| `body` | `clamp(17px, 1rem + 0.1vw, 19px)` | 400 | 1.6 | Geist Sans | All prose paragraphs, the one-liner placeholder under each section heading |
| `subhead` | `clamp(20px, 1.125rem + 0.4vw, 24px)` | 500 | 1.35 | Geist Sans | Hero subline (role + "open to AI Engineer roles") |
| `heading` | `clamp(24px, 1.25rem + 1.1vw, 32px)` | 500 | 1.2 | Geist Sans | `NumberedHeading` H2 text (e.g. "About", "Experience") |
| `display` | `clamp(36px, 1.5rem + 4.5vw, 56px)` | 500 | 1.1 | Geist Sans | Hero name only ("James Nhek") |

**Total: 5 sizes, 2 weights** — within the gsd-ui-checker dimension-4 budget (3–4 sizes + 2 weights). `display` is reserved for exactly one element on the home route (the hero name); the de-facto active type scale for the body of the page is 4 (caption, body, subhead, heading), so the contract holds.

**Letter-spacing / tracking:**
- `display`: `-0.02em` (tighter — matches the engineering-minimal voice)
- `heading`: `-0.01em`
- `caption` (mono): `0` (mono fonts handle their own rhythm)
- `body`, `subhead`: `0`

**Font-feature settings (Geist Sans + Mono, applied globally):**
- `font-variant-numeric: tabular-nums` on `caption` only (numbered anchors `01.`, `02.` must align vertically when stacked in the IA — this is the cheapest correctness win the contract gets)
- `font-feature-settings: "ss01"` is **not** enabled (Geist's stylistic alternates fight the engineering tone)

**Verified at:** 375px / 768px / 1280px — no horizontal scroll, no clipped headings, no body text rendering below 17px effective (per FOUND-06 + ROADMAP.md Phase 1 success criterion #1).

## Color

Single mode. No light/dark toggle (D-03 + REQUIREMENTS.md Out of Scope). Mono palette with a **functional accent**, not a brand accent.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (paper, 60%+) | `oklch(0.985 0 0)` ≈ `#fafafa` | Page background; site surface — the only "surface" color in v1 |
| Ink (ink, ~30%) | `oklch(0.18 0 0)` ≈ `#0a0a0a` | All primary text (body, headings, display); SVG diagram strokes |
| Ink-muted (~10%) | `oklch(0.55 0 0)` ≈ `#737373` | Numbered anchors (`01.` `02.`), captions, `<figcaption>` text, "Coming soon — …" placeholders, meta text |
| Rule (hairlines, <5%) | `oklch(0.92 0 0)` ≈ `#e5e5e5` | Borders on `Tag`, optional section separators, focus-ring outer halo |
| Accent | **same as Ink** (`oklch(0.18 0 0)`) | See "Accent reserved for" below |
| Destructive | not declared | **N/A in Phase 1** — no destructive actions exist in the shell. Phase 2's contact form (deferred to v1.x) will declare this when Resend is wired. |
| Focus ring | `oklch(0.18 0 0)` on a 2px outline with 2px offset against paper | All `:focus-visible` states — keyboard-only nav (POL-07 anticipates) |

**Why the accent equals ink:** This is a true monochrome palette. There is no second hue. The 60/30/10 split collapses to **paper / ink / ink-muted**, with the "accent" role expressed through *typographic treatment* (underline weight, mono font, tag border) rather than hue. This is the load-bearing aesthetic choice from PROJECT.md ("typography-led, monochrome, lots of whitespace") and CONTEXT.md D-03 ("no warm/paper tints, no pure black/white").

**Accent reserved for** (these are the ONLY places where typography deviates from "plain ink on paper"):
1. **`ExternalLink` underline + trailing glyph.** External links render with a `text-decoration: underline; text-underline-offset: 3px; text-decoration-thickness: 1px;` and a Geist-Mono trailing `↗` (or `→` — finalize at impl, single glyph reserved sitewide) at 0.85em. This is the ONE place where ink alone wouldn't read as "link" on a mono page. Hover state thickens the underline to 2px; no color change.
2. **`Tag` border.** Tech-stack chips render with a 1px `--color-rule` border, mono caption type, paper background, 6px × 12px padding. Border = the accent. (Phase 1 exercises this primitive but no real tags are populated until Phase 2.)
3. **`NumberedHeading` mono number.** The `01.` prefix renders in Geist Mono at `caption` size in `ink-muted`. Mono + muted is the "accent" treatment for section enumeration.

Nowhere else may a non-paper, non-ink color appear in Phase 1. No blue links. No gray surfaces. No card backgrounds.

**Contrast verification (binding, satisfies FOUND-05):**
- Ink on paper: 18.8:1 (passes 4.5:1 for body and 3:1 for large text by 4x)
- Ink-muted (`#737373`) on paper: 4.61:1 — passes 4.5:1 for body **with no margin**; treat as the floor and never darken paper or lighten ink-muted further. Used only for de-emphasized text where readability tolerance is wider (numbered anchors, captions).
- Rule (`#e5e5e5`) on paper: 1.18:1 — non-text adornment only (border on Tag, hairline separators). Never used for text. Passes 3:1-for-non-text-adjacents by failing into the "decorative" exception, but must remain ≥1px stroke width and not adjacent to other low-contrast adornments.
- Focus ring (ink on paper, 2px solid + 2px offset): visible against every interactive element on the page.

**`prefers-reduced-motion`:** Honored sitewide. Phase 1 has no motion to suppress; this is a contract for Phase 2+ never to add motion that ignores this media query.

## Components (Phase 1 Primitives)

The 5 design-system primitives from FOUND-08 + D-08. Each is a Server Component (no `"use client"` in Phase 1 per `<code_context>`). Props, slots, and states declared here are the **contract** for the executor and the audit reference for Phase 2.

### 1. `Section`

A semantic `<section>` wrapper that enforces vertical rhythm and content-column width.

**Props:**
```ts
type SectionProps = {
  id: string;                          // anchor id, e.g. "about"
  number: string;                      // "01" through "05" — passed through to NumberedHeading
  title: string;                       // "About", "Experience", etc.
  children: React.ReactNode;
};
```

**Renders:**
```
<section id={id} className="py-16 md:py-24">
  <div className="mx-auto max-w-2xl px-6 md:px-12">
    <NumberedHeading number={number}>{title}</NumberedHeading>
    {children}
  </div>
</section>
```

**Acceptance:**
- Vertical padding 64px mobile / 96px desktop
- Content column 24px gutter mobile / 48px tablet / centered max-720px desktop
- `id` becomes the scroll anchor (`#about`, `#experience`, `#projects`, `#uses`, `#contact`)
- The component never hard-codes the `"01."` prefix — that lives in `NumberedHeading` (per CONTEXT.md `<code_context>` integration point)

### 2. `NumberedHeading`

Renders the `01. About` pattern. The number is mono + ink-muted; the title is sans + ink.

**Props:**
```ts
type NumberedHeadingProps = {
  number: string;                      // "01" (no trailing dot — the component adds it)
  children: React.ReactNode;           // the title text
  as?: "h2" | "h1";                    // default "h2"
};
```

**Renders (simplified):**
```
<h2 className="flex items-baseline gap-2 mb-8 md:mb-12">
  <span className="font-mono text-[length:var(--text-caption)] text-[color:var(--color-ink-muted)] tabular-nums">
    {number}.
  </span>
  <span className="text-[length:var(--text-heading)] font-medium tracking-[-0.01em] text-[color:var(--color-ink)]">
    {children}
  </span>
</h2>
```

**Acceptance:**
- Number renders in Geist Mono at `caption` size (`tabular-nums`) in `ink-muted`
- Title renders in Geist Sans at `heading` size, weight 500
- Baseline-aligned via `items-baseline` (mono x-height differs from sans — `flex` alone won't align)
- 32–48px bottom margin to body content (`mb-8 md:mb-12`)
- Defaults to `<h2>` — `<h1>` reserved for the hero name (the only `<h1>` on the home route)

### 3. `Tag`

Tech-stack chip. Not used in Phase 1 prose, but the primitive must compile and render in isolation (per ROADMAP.md Phase 1 success #3 — primitives compile in isolation). A single demo `Tag` may appear in the dev-mode primitives exercise (see "Exercising the primitives" below).

**Props:**
```ts
type TagProps = {
  children: React.ReactNode;           // tag text, e.g. "LangGraph"
};
```

**Renders:**
```
<span className="inline-flex items-center rounded-sm border border-[color:var(--color-rule)] px-3 py-1 font-mono text-[length:var(--text-caption)] text-[color:var(--color-ink)]">
  {children}
</span>
```

**Acceptance:**
- 1px border in `--color-rule`
- 12px × 4px (8px nominal padding-y rounded to 4px-grid via `py-1` ≈ 4px) — actual: `px-3 py-1` (12px × 4px). The visual hit is a thin pill; touch target is **not** required (Tag is non-interactive).
- Geist Mono at `caption` size, ink color
- `rounded-sm` (2px corner radius — barely-there, not pill-shaped; the engineering-artifact tone resists pill chips)
- No hover state — Tags are not interactive in v1

### 4. `ExternalLink`

The only interactive element in the Phase 1 shell (and even then, in Phase 1 it has no real `href` values — the primitive just compiles. Phase 2 wires real URLs in Contact / Project cards).

**Props:**
```ts
type ExternalLinkProps = {
  href: string;                        // external URL
  children: React.ReactNode;
  showGlyph?: boolean;                 // default true; can be set false for inline links in dense prose
};
```

**Renders:**
```
<a
  href={href}
  target="_blank"
  rel="noopener noreferrer"
  className="underline underline-offset-[3px] decoration-1 hover:decoration-2 focus-visible:outline focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-[color:var(--color-ink)]"
>
  {children}
  {showGlyph && (
    <span aria-hidden="true" className="ml-1 font-mono text-[0.85em] align-baseline">↗</span>
  )}
</a>
```

**Acceptance:**
- `target="_blank" rel="noopener noreferrer"` — security default, not negotiable
- Underline at 1px thickness, 3px offset, hover thickens to 2px (no color change — accent IS the underline)
- Trailing `↗` mono glyph at 0.85em, `aria-hidden` so screen readers don't say "northeast arrow"
- `focus-visible:` 2px ink outline + 2px offset — POL-07 anticipates; Phase 1 ships the focus ring up-front
- Touch target ≥ 44×44px effective when used standalone; if inline in prose, falls back to the surrounding line-height

### 5. `ArchitectureDiagram`

Per D-08. Renders `<figure>` → image/inline-svg → `<figcaption>`. Exercised in Phase 1 with `public/diagrams/_placeholder.svg`.

**Props:**
```ts
type ArchitectureDiagramProps = {
  src: string;                         // path under public/, e.g. "/diagrams/_placeholder.svg"
  alt: string;                         // REQUIRED — not optional per D-08
  caption?: string;
};
```

**Renders (simplified — branches on extension):**
```
<figure className="my-8 md:my-12">
  {/* If src ends in .svg → use <img> for inline SVG fidelity */}
  {/* If src is raster (.png/.jpg/.webp) → use next/image with fill or explicit width/height */}
  <img
    src={src}
    alt={alt}
    className="w-full h-auto border border-[color:var(--color-rule)]"
  />
  {caption && (
    <figcaption className="mt-3 font-mono text-[length:var(--text-caption)] text-[color:var(--color-ink-muted)]">
      {caption}
    </figcaption>
  )}
</figure>
```

**Acceptance (binding for Phase 2 conformance per DIAG-03):**
- `alt` is a required prop — TypeScript enforces it at compile time, not at runtime
- `<figure>` and `<figcaption>` are semantic — not divs
- Caption renders in Geist Mono at `caption` size, `ink-muted` color
- Renders responsively at full container width; preserves intrinsic aspect ratio
- 1px `--color-rule` border surrounds the diagram (matches `Tag` treatment — visual consistency)
- 32px / 48px vertical margins (mobile / desktop)
- **Phase 1 demo:** ships `public/diagrams/_placeholder.svg` — a stub 16:9 box-and-arrow SVG (e.g. two rectangles labeled "Input" → "Process" → "Output", drawn in `#0a0a0a` strokes on `#fafafa` fill, no real architecture content). Used once on the home shell to exercise the primitive end-to-end.

## Page Composition (Home Route, Phase 1)

The home route renders, top to bottom:

1. **Hero** — outside `Section` (no number prefix). Display name + subhead role + body specialization + body availability. ~96px top padding mobile / 128px desktop, ~48px bottom padding.
2. **`Section` 01 — About** — placeholder body + (exercise) one `ArchitectureDiagram` with the placeholder SVG. This is where the primitive demo lives in production preview (avoids a separate `/_dev/primitives` route, per CONTEXT.md `<decisions>` discretion default).
3. **`Section` 02 — Experience** — placeholder body + (exercise) one inline `Tag` demonstrating the chip rendering (e.g. `<Tag>LangGraph</Tag>` shown in the placeholder text).
4. **`Section` 03 — Featured Projects** — placeholder body + (exercise) one `ExternalLink` (`<ExternalLink href="https://github.com/pjnhek">github.com/pjnhek</ExternalLink>` — real URL, Phase 1 can ship this link even if cards don't exist yet).
5. **`Section` 04 — Uses** — placeholder body only.
6. **`Section` 05 — Contact** — placeholder body only. **No `mailto:` link in Phase 1** — Contact behavior ships in Phase 2 (SEC-06).

Each section's `id` matches its anchor (`#about`, `#experience`, `#projects`, `#uses`, `#contact`) so Phase 2 (SEC-08) inherits anchor wiring with zero re-architecture.

**No navigation (header/nav) in Phase 1.** A nav element is not in scope (no Phase 1 requirement asks for one; CONTEXT.md does not mandate it; PROJECT.md's "scannable on a phone in 60 seconds" arbiter prefers a single scroll over a sticky nav). Phase 2 may add a minimal `<nav>` if anchor links become useful — that decision belongs to Phase 2's UI work, not this contract.

**No footer in Phase 1.** Same reasoning. Phase 2 may add a `/uses` link from the footer (USES-03).

## Tailwind v4 `@theme` Token Block (executor reference)

Lives in `app/globals.css`. Token names are the contract; final values may be tuned ±2% during contrast verification but the *names and roles* are binding.

```css
@import "tailwindcss";

@theme {
  /* Fonts (CSS vars set by next/font in app/layout.tsx) */
  --font-sans: var(--font-geist-sans);
  --font-mono: var(--font-geist-mono);

  /* Mono palette */
  --color-paper:     oklch(0.985 0 0);     /* #fafafa — page bg */
  --color-ink:       oklch(0.18 0 0);      /* #0a0a0a — text + diagram strokes */
  --color-ink-muted: oklch(0.55 0 0);      /* #737373 — anchors, captions, placeholders */
  --color-rule:      oklch(0.92 0 0);      /* #e5e5e5 — hairlines, tag borders, diagram borders */

  /* Type scale */
  --text-caption: clamp(13px, 0.85rem, 14px);
  --text-body:    clamp(17px, 1rem + 0.1vw, 19px);
  --text-subhead: clamp(20px, 1.125rem + 0.4vw, 24px);
  --text-heading: clamp(24px, 1.25rem + 1.1vw, 32px);
  --text-display: clamp(36px, 1.5rem + 4.5vw, 56px);

  /* Line heights */
  --leading-tight: 1.1;
  --leading-snug:  1.2;
  --leading-display: 1.1;
  --leading-heading: 1.2;
  --leading-body:    1.6;
  --leading-caption: 1.4;
}

html { color: var(--color-ink); background: var(--color-paper); }
body { font-family: var(--font-sans); font-size: var(--text-body); line-height: var(--leading-body); }
::selection { background: var(--color-ink); color: var(--color-paper); }
```
