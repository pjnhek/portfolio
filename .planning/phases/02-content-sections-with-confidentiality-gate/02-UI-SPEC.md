# Phase 2 — UI Design Contract

> Visual and interaction contract for **Content & Sections (with Confidentiality Gate)**. Generated by gsd-ui-researcher from `02-CONTEXT.md` (D-Asurion-* / D-About-* / D-Exp-* / D-Proj-* / D-Metric-* / D-Diag-* / D-Uses-* / D-Review-*), `01-UI-SPEC.md` (Phase 1 baseline), `REQUIREMENTS.md` (CONT/SEC/PROJ/USES/DIAG — 28 in-scope rows), `CLAUDE.md` (locked stack), and a direct read of every shipped primitive under `src/components/primitives/`. Verified by gsd-ui-checker.

**Tone arbiter (inherited from Phase 1, binds every close call):** *"engineering artifact, not designer's playground."* Visual reference is `huyml.co` — but more minimal. Optimize every choice for a recruiter scanning at 375px for 60 seconds.

**Inheritance rule:** Phase 2 **extends** Phase 1. The `@theme` token block, mono palette, type scale, line heights, focus-ring contract, `prefers-reduced-motion` honoring, and the 5 shipped primitives are **frozen** — Phase 2 does not redefine them. New surface area declared below: section IA, hero refinements, page-level components (`ProjectCard`, `MetricCallout`, `RoleHeader`, `ExperienceBlock`, `EducationItem`, `SiteFooter`, `CopyEmail`, `UsesEntry`, `BackLink`), per-route layouts (`/`, `/projects/[slug]`, `/uses`), the confidentiality-driven copy contract, and the accessibility contract for the first interactive surface in the codebase.

## Spacing Scale

**Inherited from Phase 1, no additions.** Phase 1 declared a 4-multiple scale through `--space-1` (4px) → `--space-32` (128px) and section rhythm of 64px mobile / 96px desktop. Phase 2 reuses every token.

**Phase 2-specific applications of the existing scale:**

| Surface | Token | Effective px (mobile / desktop) | Notes |
|---------|-------|---------------------------------|-------|
| Project-card vertical grid gap | `--space-8` / `--space-12` | 32 / 48 | Cards stack 1-col mobile; the gap is the readable rhythm between cards |
| Project-card horizontal grid gap (≥ md) | `--space-8` | 32 | Used in `grid grid-cols-1 md:grid-cols-2 md:gap-8` |
| Project-card inner padding | `--space-6` | 24 | `p-6` on the card region — keeps the card a typography artifact, not a UI surface |
| Role-header → bullets gap | `--space-4` | 16 | `mt-4` after the meta row |
| Bullet vertical gap | `--space-3` | 12 | `space-y-3` inside `<ul>` |
| Tag-row gap (chip-to-chip) | `--space-2` | 8 | `gap-2` |
| Tag-row top spacing (chips below bullets) | `--space-4` | 16 | `mt-4` |
| Role-to-role gap (within Experience) | `--space-12` / `--space-16` | 48 / 64 | `space-y-12 md:space-y-16` between `<article>`s inside Experience |
| Education sub-block top gap | `--space-12` / `--space-16` | 48 / 64 | Sits below work roles inside the same `Section` with a `--color-rule` hairline above |
| Detail-page H1 → tech-chip row gap | `--space-6` | 24 | `mt-6` |
| Detail-page tech-chip row → first `NumberedHeading` gap | `--space-12` / `--space-16` | 48 / 64 | `mt-12 md:mt-16` |
| `BackLink` (`/projects/[slug]` top, `/uses` top) — vertical position | `--space-8` / `--space-12` | 32 / 48 | `pt-8 md:pt-12 pb-4` above the page H1 |
| `SiteFooter` block padding (top + bottom) | `--space-12` / `--space-16` | 48 / 64 | `py-12 md:py-16` |
| `SiteFooter` separator hairline → text gap | `--space-8` | 32 | `mt-8` after the rule line |
| Hero → first `Section` gap | inherited Phase 1 | 96 mobile / 128 desktop (hero `pt-24 pb-12 md:pt-32 md:pb-16`) | Confirmed already in shipped `page.tsx` |

**Exceptions (Phase 2 specific):**

- **Touch targets** for the new interactive elements (project-card `<Link>`, `CopyEmail` `<button>`, `SiteFooter` links, `BackLink`, anchor links) must be **≥ 44×44 px** effective hit area. `CopyEmail` ships at minimum `min-h-[44px] min-w-[44px]` — no shrinking the visual to compress the touch target.
- **`scroll-padding-top`** on `<html>`: `4rem` (64px). When a user clicks `#about` / `#experience` / `#projects` / `#contact`, the target heading is not flush against the viewport edge. No JS scroll handler — pure CSS (D-08-discretion: "native browser behavior is sufficient"). Honored regardless of `prefers-reduced-motion`.
- **`scroll-behavior: smooth`** on `<html>` is **gated by `prefers-reduced-motion`**: declared in `globals.css` as `@media (prefers-reduced-motion: no-preference) { html { scroll-behavior: smooth; } }`. Users with reduced-motion get instant jumps. (This is the Phase 1 contract's "no motion that ignores `prefers-reduced-motion`" rule discharged.)

## Color

**Inherited from Phase 1, no additions.** Mono palette. The 4 tokens (`--color-paper`, `--color-ink`, `--color-ink-muted`, `--color-rule`) cover every Phase 2 surface, including:

- Project-card border = `--color-rule` (1px hairline, never a fill). **No card background fill.** No shadow. The card reads as a typographic block enclosed by a hairline.
- Project-card hover/focus = `--color-ink` border (1px → 1px, color only) + title color `--color-ink-muted` → `--color-ink` (Phase 1's default is already `--color-ink`, so the hover-transition is on the *subtitle* line, which moves from `--color-ink-muted` → `--color-ink`). No background fill, no scale transform, no shadow.
- `SiteFooter` separator hairline = `--color-rule`.
- `BackLink` color = `--color-ink-muted` resting → `--color-ink` on hover/focus.
- Asurion diagram (DIAG-01) strokes/labels: `--color-ink` (primary), `--color-ink-muted` (de-emphasized labels and secondary arrows). **No accent colors** (D-Diag-02). Same rule for Voice Intent Eval diagram (DIAG-02).
- `CopyEmail` button visual states: see §Components/`CopyEmail`. All ink/paper, no colored success state.

**Destructive:** still N/A. Phase 2 contact is `mailto:` + copy-to-clipboard + outbound links — no destructive actions exist on the site.

**Accent reserved for** (Phase 2 extends Phase 1's 3 entries to **5**, all monochrome — "accent" remains a *typographic* treatment, never a hue):

1. **`ExternalLink` underline + `↗` glyph** (frozen Phase 1).
2. **`Tag` border** (frozen Phase 1).
3. **`NumberedHeading` mono number prefix** (frozen Phase 1).
4. **`MetricCallout` value in Geist Mono `tabular-nums`** (new Phase 2). The accent is Mono+size, not hue.
5. **`SiteFooter` Mono ink-muted single-line nav** (new Phase 2). The accent is "Mono caption row at the page foot," sitewide.

Nowhere else may a non-paper, non-ink color appear. No blue links. No green "copied" pill. No card fills. No accent ring on hover.

## Copywriting Contract

This is the load-bearing section of Phase 2 — every word that ships is governed here. Real copy displaces Phase 1's `Coming soon — …` placeholders.

### Voice rules (binding, extends Phase 1)

Phase 1's 6 voice rules carry forward unchanged (no lorem ipsum, no marketing voice, no emoji, no exclamation, title case for headings + sentence case for body, "James Nhek" verbatim). Phase 2 adds:

7. **Conversational About voice** (D-About-02). First person. Contractions OK ("I'm", "it's"). Parenthetical asides OK. **Forbidden** even in conversational mode: "passionate", "leveraged", "cutting-edge", "synergy", "rockstar", "ninja", "I love", "let's build", "amazing", "incredible", any superlative, the word "journey". PITFALL #1 ("weekend project test") binds — every sentence must carry signal a recruiter couldn't get from the resume bullets.
8. **Every Asurion sentence on the site contains a number sourced from `.planning/refs/RESUME-2026-05.md`** (D-Asurion-03). No exceptions, no scene-setting prose, no transitional sentences without a number. If a sentence has no number, cut it.
9. **No internal Asurion product names, codenames, queue names, team names, or screenshots** (D-Asurion-04). Anywhere — copy or diagrams.
10. **Asurion diagram labels: generic role names only** (D-Asurion-04). Allowed: `Retriever`, `Reranker`, `Vector Store`, `LLM`, `Eval`, `Ingestion`. Forbidden on DIAG-01: `pgvector`, `LangSmith`, `Vertex`, `Anthropic`, or any other public-tech name. Asurion *copy* (Experience bullets) may include public-tech names the resume itself discloses (governed by D-Asurion-01); diagrams cannot.
11. **No PDF resume download button** (REQUIREMENTS.md SEC-03 forbids it explicitly).
12. **`James Nhek` (verbatim)** — never "Jim", "James N.", "JN".

### Anchor link behavior (SEC-08)

- `#about` / `#experience` / `#projects` / `#contact` are the four anchors that update the URL hash on click.

#### 9. `CopyEmail` — `src/components/interactive/CopyEmail.tsx`

**The only `"use client"` file added in Phase 2** (SEC-07). Composes `lucide-react` `Clipboard` and `Check` icons.

**Props:**
```ts
type CopyEmailProps = {
  email: string;                       // "nhekvirakyuth@gmail.com"
};
```

**State machine (binding):**

| State | Label | Icon | aria-live | Duration |
|-------|-------|------|-----------|----------|
| `idle` | `Copy email` | `<Clipboard />` (lucide-react) | (silent) | persistent |
| `success` | `Copied` | `<Check />` (lucide-react) | `Copied to clipboard` | 2000ms, then auto-revert to `idle` |
| `error` | `Copy failed — select email manually` | `<Clipboard />` | `Copy failed. Select the email address to copy it manually.` | 5000ms, then auto-revert to `idle` |

**Renders (structural):**
```jsx
"use client";
import { Clipboard, Check } from "lucide-react";
import { useState } from "react";

export function CopyEmail({ email }: CopyEmailProps) {
  const [state, setState] = useState<"idle" | "success" | "error">("idle");

  async function handleCopy() {
    try {
      await navigator.clipboard.writeText(email);
      setState("success");
      setTimeout(() => setState("idle"), 2000);
    } catch {
      setState("error");
      setTimeout(() => setState("idle"), 5000);
    }
  }

  const label = state === "success" ? "Copied" : state === "error" ? "Copy failed — select email manually" : "Copy email";
  const Icon = state === "success" ? Check : Clipboard;

  return (
    <>
      <button
        type="button"
        onClick={handleCopy}
        className="inline-flex min-h-[44px] items-center gap-2 border border-[color:var(--color-rule)] px-4 py-2 font-medium text-[length:var(--text-body)] text-[color:var(--color-ink)] hover:border-[color:var(--color-ink)] focus-visible:outline focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-[color:var(--color-ink)]"
      >
        <Icon size={16} aria-hidden="true" />
        <span>{label}</span>
      </button>
      <span role="status" aria-live="polite" className="sr-only">
        {state === "success" ? "Copied to clipboard" : state === "error" ? "Copy failed. Select the email address to copy it manually." : ""}
      </span>
    </>
  );
}
```

**Acceptance:**
- `"use client"` directive at top — **this is the only `"use client"` file added in Phase 2** (SEC-07 hard rule).
- `min-h-[44px]` enforces touch target.
- Icon size 16px (lucide-react default scale); `aria-hidden` so screen readers don't announce "clipboard icon" before the label.
- `role="status" aria-live="polite"` `sr-only` span: announces success/failure to screen-reader users. **Not** `aria-live="assertive"` — polite is correct for non-critical confirmation.
- Border 1px `--color-rule` resting → `--color-ink` on hover (no fill).
- `focus-visible:` 2px ink outline + 2px offset — matches Phase 1 `ExternalLink` pattern.
- Auto-revert via `setTimeout` — no animation, no spring. Honors `prefers-reduced-motion` trivially (no transitions to suppress).
- **Failure mode is exercised in QA**: in browsers without `navigator.clipboard` (Safari pre-13.1 — out of scope per CLAUDE.md browser targets), the catch branch fires and the user gets a usable fallback (select the address from the mailto link visible adjacent to the button).

## Accessibility Contract

Extends Phase 1's `focus-visible:` precedent to every new interactive surface.

### Heading outline (binding)

| Route | Outline |
|-------|---------|
| `/` | `<h1>` × 1 (hero "James Nhek") → `<h2>` × 4 (NumberedHeading: About / Experience / Featured Projects / Contact) → `<h3>` × 3 inside Experience (role title-company) → `<h3>` × 4 inside Featured Projects (ProjectCard title) |
| `/projects/[slug]` | `<h1>` × 1 (project title) → `<h2>` × 3 (NumberedHeading: Problem / Approach / Result) |
| `/uses` | `<h1>` × 1 ("Uses") → `<h2>` × 5 (NumberedHeading: Models / MCP Servers / Eval Stack / Agent Framework / Dev Workflow) |

Every page has exactly one `<h1>`. No skipped levels.

### Focus contract

Every interactive element ships `focus-visible:outline focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-[color:var(--color-ink)]`. This covers:

- `ExternalLink` (frozen Phase 1)
- `ProjectCard` `<Link>` (new)
- `BackLink` `<Link>` (new)
- `SiteFooter` `/uses` `<Link>` (new)
- `CopyEmail` `<button>` (new)
- Anchor `<a href="#...">` links if any in the page body (none currently planned — but if added, must conform)

### Touch targets

All interactive elements ≥ 44×44 px effective:
- `ProjectCard` `<Link>` — the card itself is much larger than 44px
- `BackLink` — enforced via `min-h-[44px] min-w-[44px]` if needed
- `SiteFooter` links — enforced via `py-2` if the caption line-height alone is < 44px
- `CopyEmail` button — `min-h-[44px]` explicitly declared
- `mailto:` and other `ExternalLink` instances — enforced by surrounding line-height or `py-2` wrapper where standalone

### Reduced-motion

`prefers-reduced-motion: no-preference` gates:
- `scroll-behavior: smooth` (declared once in `globals.css`)
- `ProjectCard` subtitle color transition (`motion-safe:transition-colors duration-150`)
- `CopyEmail` state changes (no transitions — instant swap, automatically safe)

Users with reduced motion get instant scroll jumps and no color transitions. Nothing breaks.

### Screen-reader announcements

- `CopyEmail` success / failure announced via `role="status" aria-live="polite"`.
- Decorative glyphs (`↗`, `←`, `—`, `·`, `–`) all `aria-hidden="true"` so screen readers don't announce "northeast arrow" / "leftwards arrow" / "em-dash" / "middle dot" / "en-dash" repeatedly.
- `ArchitectureDiagram` `alt` is **required at the type level** (already frozen Phase 1). Alt text describes the flow, not just the labels.

### Color contrast (binding — extends Phase 1)

All Phase 2 surfaces inherit the Phase 1 mono contrast ratios:
- Ink on paper: 18.8:1 (body text, headings, MetricCallout value)
- Ink-muted on paper: 4.61:1 (captions, mono dates, subtitles, footer text) — floor.
- `--color-rule` on paper: 1.18:1 (non-text adornment only — card border, hairline, tag border, footer hairline)

`CopyEmail` button border: `--color-rule` (1.18:1) resting → `--color-ink` (18.8:1) hover. Since the button's load-bearing affordance is the **label** (which renders at 18.8:1) and the icon (`aria-hidden`), the border's low contrast is not an a11y issue — it's a non-text adornment with adequate sibling text contrast.

### `tabindex` for in-page anchors

Each `<Section>` heading element receives an implicit `tabindex="-1"` only if browser testing confirms anchor click does not move SR focus to the heading. Tested during gsd-ui-checker pass. If needed, the `<Section>` primitive's `<section id>` element gets `tabIndex={-1}` — a minor additive change to the primitive (not a contract break, since the primitive's contract is its render shape, not the absence of `tabIndex`).

## Tailwind v4 `@theme` token usage (Phase 2 additions)

**No new tokens.** Phase 2 reuses every existing token in `src/app/globals.css`. The arbitrary-value idiom (`text-[length:var(--text-*)]`, `text-[color:var(--color-*)]`, `border-[color:var(--color-*)]`) continues from Phase 1 (locked Plan 01-02).

**One addition to `globals.css`** (NOT to `@theme`):

```css
/* Phase 2: anchor scroll behavior. Smooth scroll respects prefers-reduced-motion. */
html {
  scroll-padding-top: 4rem;
}

@media (prefers-reduced-motion: no-preference) {
  html {
    scroll-behavior: smooth;
  }
}

/* sr-only utility — Tailwind ships this, but in case Tailwind's preflight does
   not include it under v4's reset, we declare it explicitly: */
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border-width: 0;
}
```

(Tailwind v4 includes `sr-only` by default in its base layer; the explicit declaration is a defense-in-depth no-op if so.)
